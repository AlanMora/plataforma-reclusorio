01

Cómo levantarlo

Todo vive en el mismo repositorio. Un solo comando levanta infraestructura + los 10 servicios. Elige desarrollo (con hot-reload) o producción (imágenes optimizadas).

🔧 Desarrollo (hot-reload)
# infra + 10 servicios, recarga en caliente
pnpm docker:dev

# o un subconjunto
docker compose -f docker-compose.dev.yml \
  up gateway-service auth-service
🚀 Producción
# construir imágenes esbeltas
pnpm docker:prod:build

# levantar el stack
pnpm docker:prod
💻 Alternativa en el host
# solo infraestructura en docker
pnpm infra:up

# servicios con Nx en el host
pnpm install
pnpm serve
02

¿Qué endpoints existen? → Swagger

Cada servicio publica su documentación interactiva. Ahí ves cada endpoint con sus parámetros y DTOs, y puedes probarlos con el botón Authorize (token Bearer) desde el navegador.

Swagger de cada servicio en http://localhost:<puerto>/api/docs — por ejemplo http://localhost:3001/api/docs (auth) o http://localhost:3003/api/docs (core-domain). Todas las rutas de negocio están versionadas bajo /api/v1 y pasan por el gateway en el puerto 3000.
03

Flujo de la arquitectura

El gateway es la única entrada pública: pre-valida el JWT y aplica rate limiting sobre Redis, luego reenvía a los servicios internos. Cada servicio tiene su propia base de datos (database-per-service) y se comunica de forma asíncrona por RabbitMQ (patrón outbox/inbox).

06

Convenciones transversales

Todo servicio hereda estos comportamientos del núcleo compartido (libs/). Al construir encima, ya vienen resueltos.

Errores RFC 9457

Respuestas de error uniformes en application/problem+json con code estable, status, detail e instance.

Multi-tenant

El tenantId viaja en el JWT y se propaga con AsyncLocalStorage; los listados se filtran por tenant automáticamente.

Idempotencia

Los POST sensibles aceptan Idempotency-Key; la respuesta se cachea en Redis y el reintento devuelve el mismo resultado.

Outbox / Inbox

Los eventos de dominio se escriben en la misma transacción que los datos y un relay los publica; los consumidores deduplican con inbox.

JWT RS256 + JWKS

auth firma con clave privada; cualquier servicio valida con las claves públicas de /.well-known/jwks.json.

Identificadores UUID v7

Claves primarias ordenables en el tiempo, con columnas de auditoría (createdBy/updatedBy) y borrado lógico.

Observabilidad

/health, /health/ready, /metrics (Prometheus) y trazas OTLP hacia Jaeger en cada servicio.

Correlation ID

Se lee/genera x-correlation-id, se inyecta en los logs y se propaga entre servicios y eventos.
